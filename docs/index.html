3. Hak Akses & Direktori Peran Akun (Role Directory)

Sistem menerapkan Role-Based Access Control (RBAC) dengan 4 tingkat peran pengguna:

Administrator

Kontrol penuh master data siswa, alumni, guru, bank soal, jadwal ujian, backup database, dan display publik.

Pengawas / Proktor

Live monitoring peserta real-time, reset kunci perangkat (Device Lock), tambah waktu, unblock siswa, & force finish.

Guru Mata Pelajaran

Pembuatan bank soal mandiri 4 jenis (PG, PGK, Menjodohkan, Esai), pengawasan terisolasi (Teacher Scoping), & koreksi esai.

Siswa Peserta Ujian

Login single-device (1 akun = 1 gawai), pengerjaan tes terproteksi anti-cheat, dan auto-save jawaban background.

4. Panduan Tuning Server Produksi (High Concurrency)

Untuk melayani 10.000 peserta secara serentak pada server 4 vCPU / 10 GB RAM, terapkan konfigurasi tuning berikut:

4.1 Konfigurasi MariaDB (`/etc/mysql/mariadb.conf.d/50-server.cnf`)

[mysqld]
# Konkurensi & Koneksi
max_connections                = 1200
max_user_connections           = 1000
thread_cache_size              = 128
table_open_cache               = 4000
open_files_limit               = 65535

# InnoDB Buffer Pool Tuning (70% Total RAM)
innodb_buffer_pool_size        = 7G
innodb_buffer_pool_instances    = 7
innodb_log_file_size           = 1G
innodb_flush_log_at_trx_commit = 2    # Menghindari I/O Disk Bottleneck saat ribuan insert jawaban
innodb_flush_method            = O_DIRECT
innodb_read_io_threads         = 8
innodb_write_io_threads        = 8

# Query Cache (Dimatikan untuk performa multi-thread write)
query_cache_type               = 0
query_cache_size               = 0

4.2 Konfigurasi PHP-FPM (`/etc/php/8.2/fpm/pool.d/www.conf`)

pm                      = static
pm.max_children         = 120
pm.max_requests         = 1000
request_terminate_timeout = 300
rlimit_files            = 65535

4.3 Konfigurasi OPcache (`/etc/php/8.2/fpm/conf.d/10-opcache.ini`)

opcache.enable                  = 1
opcache.enable_cli              = 1
opcache.memory_consumption      = 256
opcache.interned_strings_buffer = 32
opcache.max_accelerated_files   = 20000
opcache.validate_timestamps     = 0   # Zero-disk check pada mode produksi (re-compile hanya saat restart fpm)

5. Anti-Cheat Engine & Kunci Perangkat (Device Lock)

Sistem anti-cheat CBT Nova dirancang secara *fail-safe* dengan spesifikasi aturan mutlak:

Fitur Proteksi Mekanisme Deteksi Konsekuensi Sistem
Single-Device Lock Kombinasi User-Agent, IP, dan Device Fingerprint tersimpan di cbt_device_locks. Akun ditolak jika login di perangkat kedua tanpa reset dari proktor.
Deteksi Blur / Pindah Tab Event window.onblur dan document.visibilitychange. Pelanggaran 1-2: Peringatan modal & kirim log proktor. Pelanggaran 3: Ujian Terkunci (Blocked).
Blokir Shortcut & DevTools Blokir keydown: F12, Ctrl+Shift+I, Ctrl+U, Ctrl+C, Ctrl+V, PrintScreen, Alt+Tab. Aksi dibatalkan instan (event.preventDefault()).
Auto-Save Anti-Hilang Background AJAX fetch setiap klik opsi & fallback local storage caching. Jawaban tetap tersimpan meski jaringan internet terputus sesaat.

6. Panduan Pemecahan Masalah & Protokol Insiden (Troubleshooting)

6.1 Penanganan Insiden HTTP ERROR 500 di Server Linux

1

Cek Error Log Realtime

Jalankan tail -f /var/log/nginx/error.log /var/log/php8.2-fpm.log pada terminal SSH.

2

Sinkronkan Skema Database

Jalankan mysql -u user_cbt -p'Admin-sma-11' cbt_nova_v2 < sql/sync_production_schema.sql.

3

Pastikan Ekstensi PHP Aktif

Pastikan php-fileinfo, php-gd, php-mysql, dan php-zip aktif.

4

Restart Layanan

Jalankan sudo systemctl restart php8.2-fpm nginx.

6.2 Penanganan Kendala Siswa Saat Ujian Berlangsung

  • Kasus Gawai Siswa Mati / Rusak: Buka menu Admin → Monitoring → Kunci Perangkat → Cari nama siswa → Klik tombol Reset Login. Siswa dapat langsung login di laptop cadangan dengan jawaban yang tetap utuh.
  • Kasus Siswa Terblokir (Blocked 3x): Buka menu Monitoring Proktor → Cari baris siswa yang bertanda merah → Klik tombol Buka Blokir. Status siswa kembali ke working seketika.

7. SOP Migrasi & Sinkronisasi Kode

Setiap kali ada pembaruan kode pada repositori GitHub, ikuti prosedur rilis standar berikut:

# 1. Masuk ke direktori aplikasi
cd /var/www/cbt_nova

# 2. Tarik update kode terbaru
git pull origin main

# 3. Jalankan migrasi SQL idempotent jika terdapat pembaruan skema
mysql -u user_cbt -p'Admin-sma-11' cbt_nova_v2 < sql/sync_production_schema.sql

# 4. Pastikan izin kepemilikan file tetap benar
sudo chown -R www-data:www-data /var/www/cbt_nova
sudo chmod -R 755 /var/www/cbt_nova
sudo chmod -R 775 /var/www/cbt_nova/assets/uploads

# 5. Refresh cache OPcache & PHP-FPM
sudo systemctl restart php8.2-fpm nginx
